# kagiya の限界（免責事項のもと）

kagiya が**保証しないこと・分からないこと・見ていないもの**の一覧。
利用者向けの免責事項を書くときの材料として、実装や実物確認の過程で分かったことを随時追記する。

- 「恒久」: 設計上の方針によるもので、今後も変わらない。
- 「現時点」: まだ実装・確認していないだけで、今後解消する予定があるもの。

最終更新: 2026-11-12（Phase 1c の途中。sshd の実効値まで）

---

## 1. 「通信しない」ことの保証範囲

| 限界 | 区分 | 説明 |
|---|---|---|
| 保証するのは本プロセスの挙動まで | 恒久 | 保証するのは「本プロセスが通信用の機能を使わない」「ネットワーク越しのファイルシステム（NFS、SMB など）と、開くと取得が発生するファイルに触れない」こと。次のものは検出も制御もできない: ブロックレベルのネットワークストレージ（iSCSI、SAN など）上のローカルファイルシステム、アンチウイルス・EDR によるクラウド照会、OS の監査ログの転送など、第三者による間接的な通信 |
| マウント表の取得後に現れたマウント | 恒久 | スキャン中に新しくマウントされたネットワークファイルシステムは、開いた後のデバイス番号の照合で検出して読まないが、ディレクトリを開く操作そのものは発生し得る |
| 走査中にディレクトリが差し替えられた場合 | 現時点 | 走査中のディレクトリが、確認の直後に同じ場所でシンボリックリンクへ差し替えられると、その行き先のディレクトリを開いてしまうことがある（開いた後の照合で検出して中身は読まないが、開く操作そのものは発生し得る。行き先がネットワークファイルシステムなら通信になる）。スキャン対象のディレクトリに書き込める利用者が、タイミングを合わせて行う必要がある。リンクを辿らない方法でディレクトリを開く実装に置き換える予定 |
| 実行時の封じ込めはベストエフォート | 恒久 | Linux の seccomp は、適用できない環境（古いカーネル、既存のサンドボックス内、エミュレーション環境）では適用されないまま処理を続ける。適用の成否は結果に記録する。主たる保証は「通信コードを持たない」こと |
| Windows での封じ込め | 現時点 | 未実装 |

## 2. 見ていないもの（探索範囲）

| 限界 | 区分 | 説明 |
|---|---|---|
| ネットワークファイルシステム上のファイル | 恒久 | 読まない（スキップとして記録する）。そこにある証明書・鍵・設定は結果に現れない |
| 種別が不明なファイルシステム | 恒久 | 分類表にない種別は安全側に倒して読まない。コンテナのバインドマウントや独自のファイルシステムが該当し得る |
| シンボリックリンクの先 | 恒久 | 探索ではリンクを辿らない。リンク経由でしか到達できない場所にあるファイルは見つからない（共有ライブラリと証明書ストアの特定では、安全を確認しながら辿る） |
| 既定の探索起点の外 | 恒久 | 既定では `/etc`、`/opt`、`/usr/local`、`/srv`、`/var/www`、`/root` と証明書ストアの場所だけを探す。`/home` やその他の場所は、指定しない限り見ない |
| 名前や拡張子から鍵素材と分からないファイル | 恒久 | 候補は拡張子・ファイル名で選ぶ。拡張子のないファイルは 16 KiB 以下のものだけ中身を見る。独自の名前・拡張子で置かれた大きな鍵ファイルは見つからない |
| 大きすぎるファイル、深すぎる階層 | 恒久 | 上限（既定で 64 MiB、64 階層）を超えるものは読まない（スキップとして記録する） |
| 読み取り権限のないもの | 恒久 | 記録して先へ進む。一般ユーザーで実行した場合、秘密鍵や一部の設定は見えない。権限を迂回する操作は行わない |
| コンテナの中、コンテナイメージ | 現時点 | ホストからコンテナ内部やイメージ層は調べない。コンテナ内で kagiya を実行することはできる |
| 他のマウント名前空間 | 恒久 | 自プロセスから見えるファイルシステムだけが対象 |
| ハードウェア（HSM、TPM）内やメモリ上の鍵 | 恒久 | 対象外 |

## 3. 中身を確認できないもの

| 限界 | 区分 | 説明 |
|---|---|---|
| パスワードで保護されたキーストア・秘密鍵の中身 | 恒久 | パスワードは一切使わない。暗号化された PKCS#12 の中の証明書などは「確認できない」と記録するにとどまる。最近の Java の既定のキーストア形式（PKCS#12）は証明書も暗号化するため、中身が見えないものが多い |
| 公開成分を含まない秘密鍵と、証明書との対応 | 恒久 | 秘密成分を使った計算は行わない。OpenSSL が出力する Ed25519 や DSA（PKCS#8）の秘密鍵、暗号化された秘密鍵は、公開鍵の指紋が得られず、証明書や SSH 公開鍵と対応づけられない |
| JCEKS の共通鍵エントリ以降 | 現時点 | 共通鍵エントリに出会うと、そこで読み取りを打ち切る（「途中まで読んだ」と記録する） |
| 未対応の形式 | 現時点 | PGP 鍵、PuTTY の PPK、NSS のデータベース、BKS キーストアは未対応 |
| カタログにないアルゴリズム | 恒久 | 「未知」として記録する。評価（危殆化、量子耐性）は付かない |

## 4. 「使われているか」について

| 限界 | 区分 | 説明 |
|---|---|---|
| 実際にネゴシエーションされている暗号 | 恒久 | 設定から分かるのは「許可・提示されている」ものまで。相手との間で実際にどれが選ばれているかは、通信を観測しないと分からない |
| 「有効」と「稼働中」の差 | 恒久 | 起動するよう設定されていても止まっていることがあり、手動起動やソケット起動で動いていることもある。稼働中かどうかは、明示的に指定した場合（`--process-info`）にだけ調べる |
| クライアントとしての利用 | 恒久 | 定期実行されるスクリプトなどからの利用は、サービスとしては見えない |
| ソースコードと本番の関係 | 恒久 | ソースコードに書かれた処理が、本番で動いているとは限らない |
| ログに残る実績 | 恒久（v1） | ログは読まない |
| 証明書の信頼性・有効性 | 恒久 | 署名の検証、信頼の連鎖の検証、失効の確認は行わない（通信が発生し得るため）。記録するのは証明書に書かれた内容 |

## 5. 版と既定値の特定について

| 限界 | 区分 | 説明 |
|---|---|---|
| 環境変数による差し替え | 恒久（既定） | `LD_LIBRARY_PATH`、`LD_PRELOAD`、`OPENSSL_CONF` などによるライブラリや設定の差し替えは分からない。稼働中プロセスの環境変数は読まない |
| 実行時に読み込まれるモジュール | 恒久（既定） | ルールに定義したもの（Apache の `mod_ssl.so` など）以外の、実行時に読み込まれるモジュールやプラグインは分からない |
| 静的リンクされた暗号ライブラリ | 現時点 | 共有ライブラリとしてリンクされているものだけを特定する |
| コンポーネントとパッケージの対応 | 現時点 | 名前による推定。同じライブラリの複数の版が導入されている場合、対応を誤る可能性がある |
| パッケージ管理外で導入されたソフトウェア | 恒久 | パッケージの版は付かない。バイナリに埋め込まれた版文字列だけが手がかりになる |
| 更新途中のパッケージ管理データベース | 恒久 | コマンドを使わずファイルを直接読むため、更新の最中は整合しない部分を読み飛ばすことがある（件数を記録する） |
| 未対応のパッケージ管理形式 | 現時点 | rpm の NDB 形式（SUSE 系）は未対応 |
| 実物で確認していないディストリ・版 | 恒久 | ルールの既定値や対応表は、出典として記録したイメージ・パッケージ版で確認したもの。それ以外の環境では、値が当てはまらない可能性がある（信頼度を下げて記録する） |
| RHEL の確認範囲 | 恒久 | Red Hat Universal Base Image とそのリポジトリの範囲で確認している |
| OS 暗号設定の対応範囲 | 現時点 | 読むのは、システム全体の暗号ポリシーの名前、カーネルの FIPS モード、OpenSSL のシステム既定の TLS 設定まで。GnuTLS、NSS、Kerberos、Java、libssh などの設定は未対応 |
| OpenSSL 設定ファイルの変数 | 恒久 | 設定ファイル中の変数（`$var`、`$ENV::NAME`）は展開しない。変数を含む値は「解釈しなかった」と記録し、値としては採らない |
| OpenSSL 設定ファイルの相対パスの取り込み | 恒久 | `.include` が相対パスの場合は辿らない（基準となるディレクトリが実行時の環境で決まるため） |
| 記録する設定項目 | 恒久 | 設定ファイルから記録するのは、ルールで許可した項目だけ。それ以外の項目は「記録対象外」として件数だけ残す |
| ビルド時に決まる既定値 | 現時点 | OpenSSL のセキュリティレベルの既定は、暗号スイートの対応表（パッケージ版ごとの実測）から、nginx と Apache の暗号スイートの実効値に反映している。それ以外の、設定ファイルに現れない既定値（署名アルゴリズム、鍵交換のグループなど）は、まだ結果に反映していない |
| カーネルの FIPS モード | 現時点 | 読み取りは実装したが、実物（FIPS モードのホスト）では未確認。検証に使ったコンテナには該当のファイルがなかった |
| 実効値を求められるアプリと項目 | 現時点 | 実効値（設定の記載と既定値から求めた、実際に効く値）を求めるのは、sshd の各アルゴリズムの一覧と、nginx・Apache httpd・HAProxy の暗号スイート（TLS 1.2 以下と TLS 1.3）。プロトコル、鍵交換のグループ、署名アルゴリズムは、設定に明記された値の記録まで |
| 既定値表・対応表にないパッケージ版 | 恒久 | 記載のない項目の実効値は、導入されているパッケージ版に対応する実測の表がある場合にだけ求める。表にない版（未採取のディストリ・版、独自ビルドなど）では「不明」とし、推測では埋めない。パッケージ名・上流の版・ディストリの系列が同じでリリース番号だけが違う版（エラータ）に限り、実測した版の表で補間する（sshd・nginx・Apache の既定値表と、OpenSSL の暗号スイートの対応表のいずれも）。補間した結果には、実測した版と導入されている版を注記に残し、確度を一段下げる。リリースの違いで既定値が変わっていた場合、補間した値は実際と異なる |
| パッケージの更新で既定値表が古くなる | 恒久 | ディストリがパッケージを更新すると、版の文字列が変わり、表と完全には一致しなくなる。リリースだけの違いなら補間で求まるが（確度は一段下）、上流の版が変わると「不明」になる。表は、採取し直して更新する必要がある（採取は自動化しておらず、必要なときに手動で行う） |
| sshd の実効値で解決しない書き方 | 恒久 | ワイルドカードを含む追加・先頭指定（`+...*`、`^...*`）と、ワイルドカードを含む一覧の明記は、その版が対応する全アルゴリズムの一覧が要るため「不明」とする（削除でのワイルドカードは解決する） |
| sshd の条件付きの設定と実効値 | 恒久 | 実効値は、全体に適用される設定から求める。Match ブロックの中の設定による接続ごとの違いは反映しない |
| 対応しているアプリの設定 | 現時点 | 設定値を読むのは OpenSSH サーバー（sshd）、nginx、Apache httpd、HAProxy の4つ。その他のアプリは未対応 |
| nginx・Apache の階層間の引き継ぎと上書き | 現時点 | 外側の値が内側に引き継がれる規則を解決しているのは、暗号スイート（nginx の `ssl_ciphers`、Apache の `SSLCipherSuite`）、証明書、DH パラメータの指定だけ。それ以外の項目は、書かれている範囲（http 全体、どの server / VirtualHost）とともに記録するにとどまる。nginx の `stream` / `mail` の中の server は、引き継ぎの確認をしていない |
| nginx・Apache の設定中の変数 | 恒久 | 変数を含むパス（nginx の `$変数`、Apache の `${変数}`）は、どのファイルかを確定できないため記録しない（「解釈しなかった」として件数に残す）。Debian 系の Apache は、ログの場所などに環境変数を使っている |
| nginx の古い書き方 | 現時点 | TLS を使う待ち受けは `listen ... ssl` の形で判定する。古い書き方（`ssl on;`）は TLS の待ち受けとして認識しない |
| Apache のモジュールの判定 | 恒久 | `<IfModule>` の条件は、設定ファイル中の LoadModule の記載から判定する。本体に組み込まれたモジュールは分からないため、その条件の中身は採らない |
| Apache の起動時の指定 | 恒久 | `<IfDefine>` の条件は、起動時の指定（`-D`）が分からないため、定義されていないものとして扱う |
| Apache のディレクトリ単位の設定 | 恒久 | `.htaccess` は読まない。ディレクトリを指定した Include は、その直下のファイルだけを読む |
| Apache の待ち受けポート | 現時点 | 記録する Listen は、TLS を有効にした `<VirtualHost>` と同じポートのものと、`https` の指定があるものだけ |
| OpenSSL の設定を直接変える書き方 | 現時点 | nginx の `ssl_conf_command`、Apache の `SSLOpenSSLConfCmd` が書かれている範囲は、暗号文字列だけでは結果が決まらないため、暗号スイートの実効値を「不明」とする。Apache の `SSLCipherSuite TLSv1.3 ...`（TLS 1.3 のスイートをアプリの設定で指定する書き方）は、TLS 1.3 の側だけ「不明」とする。Apache の `mod_md`（証明書の自動取得）や `mod_gnutls` の設定は記録していない |
| 暗号スイートの実効値が示す範囲 | 恒久 | 示すのは「そのサーバーが受け入れ得るスイートの集合」。どのプロトコル（TLS 1.0〜1.3）が有効かは、まだ解決していない（TLS 1.3 のスイートは「TLS 1.3 が有効な場合に使われるもの」として別の項目で示す）。並びは暗号文字列の展開順で、サーバーの優先順として実際に使われるかは設定（`ssl_prefer_server_ciphers`、`SSLHonorCipherOrder`）による。実測で確かめたのは集合の一致までで、優先順は測っていない |
| 暗号スイートの絞り込みの前提 | 恒久 | 事前共有鍵（PSK）と SRP のスイートは、アプリ側の追加の設定がないと使えないため、使えないものとして扱う（Apache で SRP を設定している場合は当てはまらない）。証明書の種類は、設定が指す証明書ファイルの先頭の証明書から判定する。証明書を読めない場合（権限がない、まだ作られていない、変数を含む指定など）は、種類による絞り込みをせずに求め、確度を一段下げる。証明書の鍵長や署名がセキュリティレベルを満たすか（満たさないとサーバーは起動できない）は確認していない |
| システムの OpenSSL 設定の適用 | 恒久 | セキュリティレベルと TLS 1.3 のスイートは、システムの openssl.cnf（RHEL 系では暗号ポリシーが生成した内容）の既定が、そのサーバーに適用される前提で求める。環境変数（`OPENSSL_CONF`）で別の設定ファイルに差し替えられている場合や、アプリが設定の読み込みを無効にしている場合は当てはまらない |
| DHE を使えるかの判定 | 現時点 | nginx は `ssl_dhparam` の指定があれば使えるとし、なければ版ごとの実測（古い版は組み込みのパラメータを持つ）に従う。Apache は組み込みのパラメータで使えるとする（証明書ファイルに付けた独自のパラメータや、鍵長とセキュリティレベルの関係は見ていない）。その版の実測がなければ、DHE のスイートを残したまま確度を一段下げる |
| Debian 系の Apache の組み込みの既定 | 現時点 | Debian・Ubuntu の Apache は、パッケージの設定ファイルが必ず `SSLCipherSuite` を書いているため、mod_ssl に組み込まれた既定の暗号文字列を実測できていない。その記載を消した構成では、暗号スイートの実効値は「不明」になる |
| 同じ名前の server / VirtualHost | 現時点 | 実効値は範囲の名前（最初の `server_name`、VirtualHost の宛先）で区別する。同じ名前の範囲が複数あると、結果の上で区別が付かない |
| HAProxy の証明書の選ばれ方 | 恒久 | HAProxy は、サーバー名（SNI）のない接続には最初の証明書だけを使う。実効値は「指定されたどの証明書も選ばれ得る」前提の集合で、サーバー名を付けない接続で受け入れられる集合より広いことがある。証明書をディレクトリや一覧ファイル（`crt-list`）で指定している場合は、どの証明書が使われるかを追わず、種類による絞り込みをしない（確度は一段下） |
| HAProxy の設定で見ていないもの | 現時点 | 実効値を求めるのは、frontend / listen の `bind` の待ち受けだけ。`defaults` の節の値の引き継ぎ、backend の `server` 行（外向きの接続）の暗号指定、`ssl-default-bind-options` や `ssl-min-ver` によるプロトコルの制限は、記録するか未対応のいずれかで、実効値には反映していない。証明書に付けた DH パラメータも見ていない |
| HAProxy が読む設定ファイル | 現時点 | 読むファイルは、ユニットの起動コマンドの `-f` の指定に従う（なければ `/etc/haproxy/haproxy.cfg` だけ）。複数のファイルにまたがる節の続き方は実物で確かめていない（ファイルごとに節が始まるものとして読む）。環境変数を含む行は値を展開せず、その行の指定は採らない |
| Apache のディレクトリ単位の暗号指定 | 恒久 | `<Directory>` や `<Location>` の中の `SSLCipherSuite`（接続後の再ネゴシエーションで適用される）は、暗号スイートの実効値に反映しない |
| OpenSSL の暗号文字列で展開しない書き方 | 恒久 | `SUITEB128` などの特別な語は展開しない（「不明」とする）。その版が知らない語は、OpenSSL と同じく無視する |
| 複数の版の OpenSSL | 現時点 | 対応表のある OpenSSL のパッケージが複数導入されている場合、そのサーバーがどれを使うかを決められないため、暗号スイートの実効値は「不明」とする |
| 条件付きの設定 | 恒久 | sshd の Match ブロックの中の設定は「条件付き」として記録する。どの接続に適用されるかは判定しない |
| systemd の上書き設定 | 現時点 | ユニットの一部だけを上書きするドロップイン（`<ユニット名>.d/*.conf`）は読んでいない。そこで起動引数や環境ファイルが変えられている場合は反映されない |
| systemd 以外の起動方法 | 現時点 | サービスの有効化状態は systemd の定義から読む。SysV init のスクリプト、コンテナの起動コマンド、手動起動は分からない |
| 設定ファイルの場所の指定 | 現時点 | 起動引数で設定ファイルの場所が変えられている場合（sshd の `-f` など）は追っていない |
| 秘密鍵と対になる公開鍵ファイル | 現時点 | 設定から参照されている秘密鍵には利用の確からしさが付くが、同じ場所にある対の公開鍵ファイル（`*.pub`）には付かない |
| 設定中のアルゴリズム名と暗号カタログ | 現時点 | 設定に書かれた SSH のアルゴリズム名は文字列として記録するだけで、暗号カタログの資産とは結び付けていない（評価の対象にまだならない） |
| 独自にビルド・改変されたソフトウェア | 恒久 | ビルド時のオプションや独自のパッチによる既定値の違いは分からない |

## 評価とレポートについて

| 限界 | 区分 | 説明 |
|---|---|---|
| 評価は目安 | 恒久 | 判定は、評価ポリシーが根拠にした文書（NIST IR 8547、CRYPTREC 暗号リストと暗号強度要件、RFC 8996、RFC 9142）に照らした目安。個々のシステムで移行が必要か、いつまでに行うかは、扱う情報と利用期間に応じて利用者が判断する。文書が改定されれば、ポリシーの更新が要る |
| 文書によって扱いが違うもの | 恒久 | AES-128 と SHA-256 は、CRYPTREC の耐量子計算機暗号リストに載っていないため「量子計算機で強度が下がる」と判定する。NIST は置き換えを求めていない。どちらの基準で見るかで結論が変わる |
| 文書に記載のない方式 | 恒久 | 参照した文書に記載のない方式（ARIA、SEED、IDEA、UMAC、bcrypt など）と、暗号カタログにない方式は「判定できない」とする。安全とも危険とも言っていない |
| TLS 1.3 の鍵共有 | 現時点 | TLS 1.3 の暗号スイートは、量子計算機に対する評価を「判定できない」とする。鍵共有はグループの設定で決まり、その実効値をまだ求めていない |
| 自己署名のルート証明書の署名方式 | 現時点 | 証明書は、鍵と署名の方式のうち厳しいほうで判定する。信頼の起点になるルート証明書の自己署名は安全性に影響しないが、区別せずに判定している（SHA-1 で自己署名された古いルート証明書が「危殆化」と出る） |
| 証明書の判定に使う情報 | 恒久 | 証明書の判定は、鍵の種類と長さ、署名の方式による。用途、発行元の信頼性、失効、名前の一致は見ていない |
| 評価の対象になる設定値 | 現時点 | 設定のうち評価するのは、実効値を求められた項目（暗号スイート、SSH の各方式）と、設定に書かれた TLS のプロトコルの版。鍵交換のグループ、署名アルゴリズムの設定、外向きの接続の設定は評価していない |
| 要点の数え方 | 恒久 | 要点の数は、サービス・範囲ごとに許可されている方式の延べ数。同じ方式が複数の範囲で許可されていれば、その数だけ数える。「起動するよう設定されたサービス」だけを数え、導入されているだけのサービスは含めない |
| 期限の判定 | 恒久 | 証明書の期限切れ・期限間近は、スキャンした時点を基準に判定する。レポートを開いた日ではない |
| レポートの対象 | 現時点 | HTML レポートは 1 ホスト分だけ。複数ホストのまとめ（`merge`）は未実装 |
| レポートの言語と操作 | 現時点 | 日本語のみ。スクリプトを使わないため、並べ替えや絞り込みはできない（ブラウザの検索を使う） |

## 7. 負荷と副作用

| 限界 | 区分 | 説明 |
|---|---|---|
| 本ツールの制御外の負荷 | 恒久 | ファイルを開くことで、アンチウイルスのリアルタイムスキャン、ファイルアクセスの監査ログ、EDR の検知が発生し得る。これらの負荷や通知は本ツールの優先度・流量制限の外にある |
| アクセス時刻の更新 | 現時点 | 読んだファイルのアクセス時刻が更新され得る（マウントオプションによる） |
| 流量制限の既定値 | 現時点 | CPU 使用率・読み取り速度の既定値は暫定で、負荷試験による裏付けはまだない |
| 優先度の低下 | 恒久 | 低下できない環境では、警告を記録して処理を続ける |

## 8. 出力について

| 限界 | 区分 | 説明 |
|---|---|---|
| 出力は機微情報を含む | 恒久 | 秘密鍵やパスワードの値は含まないが、ファイルパス、ホスト名、証明書の Subject、ソフトウェアの版などを含む。出力ファイルは作成者だけが読める権限で作るが、その後の取り扱いは利用者の責任 |
| ハードリンクも「上書きしない改名」も使えない出力先 | 恒久 | 結果ファイルは、既存のファイルを上書きしない方法（ハードリンク、または上書きしない改名）で確定する。どちらも使えない出力先では、スキャンの前にエラーで止まる。Linux 以外では「上書きしない改名」に対応していないため、ハードリンクを作れないファイルシステム（vfat、exfat など）には出力できない |
| ハードリンクを作れないファイルシステムでの確認 | 現時点 | vfat / exfat を実際にマウントした環境での確認は未実施（上書きしない改名そのものは、実際のカーネルで動作を確認した） |
| 出力先の権限 | 恒久 | グループや他のユーザーが書き込める出力先、実行ユーザーと root 以外が所有する出力先は拒否する |
| CSV は情報量が落ちる | 恒久 | 出現1件1行に平坦化するため、キーストアの詳細やリンク関係などは含まれない |
| データ形式は未確定 | 現時点 | 結果 JSON の形式は v0 で、互換性を保証しない |
| 評価（危殆化、量子耐性） | 現時点 | 未実装 |
